# tree-sitter-minml

A [tree-sitter](https://tree-sitter.github.io/tree-sitter/) grammar for MinML.
Zed and Helix use it for highlighting and indentation; the `minml-lsp` language
server does the rest.

## Equivalence with the Go parser

The grammar accepts exactly the documents that the Go parser in
[`go/markup/minml`](../../go/markup/minml) accepts, and gives elements,
attributes, character references, comments, and raw text the same source ranges.
The Go parser drops empty comments and raw text; the grammar keeps them as nodes.

`bindings/go/minml_test.go` checks this: it parses the MinML files in
[`test`](../../test), the inputs of `test/corpus`, and random documents with both
parsers and compares the results. It also checks that reparsing after an edit, as
editors do, gives the same tree as a fresh parse on valid documents. Change the
grammar and the Go parser together, and run:

```sh
make test-grammar   # from the repository root
```

## Structure

| Node | Source |
| --- | --- |
| `element` | `name{attributes}[content]`, with fields `name`, `attributes`, `content` |
| `tag_name` | a run of non-space, non-matcher characters directly before `[` or `{` |
| `attributes`, `attribute`, `attr_name` | `{name=value ...}`, names are XML names |
| `value`, `quoted_value` | `name=value` ends at whitespace; `name=[...]` holds text and references |
| `reference` | `[amp]`, `[#174]`, `[[<]]`: no whitespace and no matchers inside |
| `comment`, `raw` | `-[...]` and `+[...]`: only matchers must balance inside |
| `literal` | any other matcher pair: `(...)`, `[...]`, `{...}` |

`src/scanner.c` makes the decisions that depend on the next characters: whether a
run of characters is an element name, whether `[...]` is a reference, and whether
a run is an attribute name. `grammar.js` explains each rule.

## Building

`src/` is generated by `make gen-parser` (`tree-sitter generate`) and committed,
because Zed and Helix build the parser from it. The Go binding compiles the same
sources with cgo.
