\section{Matchertext literals in Go: experiment details}
\label{app:go}

The patch of \cref{sec:impl:go} adds \verb|M"(|$\dots$\verb|)"|,
\verb|M"[|$\dots$\verb|]"|, and \verb|M"{|$\dots$\verb|}"|
to \texttt{cmd/compile/internal/syntax}, \texttt{go/scanner}, and \texttt{go/constant}.
The content of such a literal is its value verbatim:
it has no escapes, and unlike in Go's backquoted raw strings
its carriage returns are kept.
The scanner rejects a literal whose content is not matchertext,
or whose closing matcher no quote follows.

The rewriting tool converts an interpreted literal \verb|"|$\dots$\verb|"|
only if the literal has a backslash,
its source text and its value are matchertext,
and its value is valid UTF-8 with no NUL, byte-order mark,
or control character other than line feed and tab.
It leaves import paths and struct tags unchanged, which the compiler unquotes itself,
and skips \texttt{testdata} and \texttt{vendor} directories
and files that use cgo.
Unlike the corpus rewriting of \cref{sec:eval:methodology},
which normalizes control characters,
it therefore preserves every value exactly
and leaves literals of control characters or binary data as they are.

\Cref{tab:app:go} lists the four repositories,
pinned to the commits tested.
Each was tested with \verb|go test -short ./...| three times:
with stock Go, with the patched toolchain on the unchanged code,
and with the patched toolchain after rewriting the repository's own code.
Dependencies came unchanged from the module cache,
so the patched toolchain also compiled them unmodified.
The pass, fail, and skip outcome of every package
was identical across the three runs.
The 88 toothpicks left in the rewritten literals
are backslashes of the value itself, written by \verb|\\| or another escape
that decodes to a backslash.
The artifact includes the patch, the tool, the script, and these results.
